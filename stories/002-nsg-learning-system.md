# Story 002: 從 20 個主題到 6 個 — 用 AI 設計學習系統

## 問題

想學的東西太多，同時排了 20 個主題、每天 4 小時，結果什麼都沒開始。

知道要做，但不知道從哪個開始。排了完美計劃，三天就放棄。

## 過程

### Phase 1：在 Claude.ai 上設計系統骨架

跟 Claude 對話，用 brainstorming → planning → execution 的工作流，一步步產出：

1. **系統定義**：先定義核心公式（專注力 × 時間預算 × 使命感），寫出使命感宣言
2. **斷捨離**：用「未來 90 天內對使命感有直接貢獻嗎？」篩選，20 個主題砍到 6 個
3. **排程設計**：A/B 組交叉（一三五/二四），5 個時段，每天 3 小時
4. **失靈訊號**：定義 6 個警示燈，系統出問題時知道怎麼修

這個階段產出 5 份文件：系統核心定義、斷捨離結果、時段表、引導腳本、技術規格。

### Phase 2：交給 OpenClaw 落地

把設計文件帶進 OpenClaw 環境，開始實作：

1. **學習排程**：從 Markdown 轉成 JSON（`schedule.json`），機器可讀
2. **打卡格式**：設計 4 步驟學習紀錄（提取 → 差距 → 今日所學 → 使命連結）
3. **Cron 提醒**：5 個學習時段 + 1 個週報，自動推送到 Telegram
4. **HTML 儀表板**：先做基礎版，再用 worker agent 做遊戲化改版

### Phase 3：遊戲化（Octalysis 八角框架）

派 worker agent（Sonnet 模型）把儀表板改成遊戲化版本：

- 等級系統：Lv.1 啟動者 → Lv.5 自由者（對應 Daniel Pink 動機層次）
- 連續火焰 🔥：streak 計數，斷掉會變灰
- 成就徽章：早鳥、三力齊發、完美週等
- 打卡後金色閃光動畫

Worker agent 6 分鐘交付，我再花 15 分鐘微調細節（字體、透明度、RWD）。

## 關鍵決策

### 為什麼用乘法公式？

三力是乘法關係（專注力 × 時間預算 × 使命感），任一為零則全盤歸零。這不是雞湯，是設計約束——系統必須同時照顧三個維度。

### 為什麼砍到 6 個主題？

認知科學的實證：同時學超過 6 個主題時，提取練習（retrieval practice）的效果急遽下降。每個主題的間隔太長，大腦來不及鞏固。

### 為什麼用 A/B 組交叉？

交叉學習（interleaving）比集中學習在長期記憶留存上高 20-30%。一三五學 A 組、二四學 B 組，自然形成間隔。

### 為什麼 main agent 不自己改 HTML？

65KB 的 HTML 改版是耗時的執行型任務，不需要 Opus 的推理能力。派 Sonnet worker 做，main 繼續跟人對話。這就是 agent 分工的價值。

## 結果

- **20 個主題 → 6 個主力 + 維持型**，時間從 240 分鐘降到 180 分鐘
- **5 份設計文件** 歸檔在 `docs/`，系統有據可查
- **遊戲化儀表板** 可本地使用，也可部署到雲端
- **自動提醒** 每天 5 個時段推送，不靠意志力啟動
- 進入四週測試期，用數據驗證排程是否可行

## 學到的事

1. **AI 對話適合設計，OpenClaw 適合落地。** Claude.ai 的對話式探索很適合釐清模糊需求，但產出的文件需要帶進工程環境才能變成可運作的系統。

2. **斷捨離比排程重要。** 花 80% 時間在決定「不做什麼」，排程反而 10 分鐘就搞定。

3. **系統最小啟動點是入口，不是功能。** 再完整的系統，沒有一個低摩擦的每日入口就不會被使用。
